## Decisions

See `docs/DECISIONS.md` (six rows dated 2026-10-27 for B8): the Bulk window, people who asked not to be called, the defaults, consent, shared channels and the rule-table pause, and how a repeat and a restore work.

- **The contact owns the retries.** A campaign call has no follow-up `Call` row: the contact carries `attempts` and `next_attempt_at`, and the scheduler makes the next call when it is due.
- **Checked again at the last moment.** Upload-time checks only decide how a row is stored; every rule is applied again just before the dial, inside the same transaction that marks the call ringing.
- **Unknown beats wrong.** A dial whose answer was lost, or a call the carrier never reported, is never retried and never charged blind.

## Open items

- A start time must carry a time zone; one without is refused (422).
- A real 20-contact campaign needs the Vobiz keys and public URLs (Track 3, WIRING). Everything here is tested against a recording carrier.
- Defaults (2 calls at once, 2 retries an hour apart, 7-day dedupe) are for the owner to confirm.
- The export writes `'+91…` for phone numbers (the shared CSV guard treats a leading `+` as a formula), so a re-upload of an export needs the apostrophe removed.
- Free test calls are counted as busy only once answered; the few seconds of ringing do not hold a channel.
- A campaign paused by a rule refusal needs the owner to fix the rule or number and resume it; there is no automatic retry.
- The DNC list's own screens (single and bulk add, reasons) are B13; B8 only reads the list.
- Consent (review note): the cautious reading is used. Contacts added after the owner's confirmation pause a running or scheduled campaign, and the campaign neither starts nor resumes until the owner confirms again (a campaign still waiting for its start time goes back to waiting when resumed) (`consent_given` on the campaign is false until then). The owner may prefer a lighter rule.
- A pasted list carries no variables, so the import report names the script variables left empty (`variables_left_empty`).
- A repeating campaign's next run does not retry a contact held for an unknown outcome; a person has to check it with the carrier.
- The capacity preview assumes half the contacts need one retry; it is an estimate, not a promise.

## How to run

```bash
docker compose -f deploy/docker-compose.yml up -d postgres redis
uv run alembic -c services/api/alembic.ini upgrade head && uv run python -m app.voices
AXON_TEST_DATABASE_URL=postgresql+asyncpg://axon:axon@localhost:5432/postgres AXON_TEST_REDIS_URL=redis://localhost:6379/5 uv run pytest
```

The worker (`arq worker.main.WorkerSettings`) runs the campaign tick every three seconds. A campaign needs a live Bulk employee on a number whose type the dial rule table allows for the campaign's purpose (a promotional campaign needs a 140-series number by default).
