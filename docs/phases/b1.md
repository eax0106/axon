## Schema notes

- **Number types** `regular` / `140` / `1600` on `numbers.number_type`; **purpose** `promotional` / `service` / `transactional` on `employees.purpose`, with an optional per-campaign override `campaigns.purpose` (DECISIONS: purpose rule table). The rule table itself is B7.
- **Numbers are released, not deleted.** `uq_numbers_e164_held` is a partial unique index (`WHERE status <> 'released'`), so a released number can be bought again while a held number can't be duplicated.
- **Account roles vs platform staff.** `users.role` is `owner` or `member` only (CHECK constraint). ALTERX staff access is `users.is_platform_admin` (default false), never set through the API, so no account role can ever reach admin routes.
- **Enums are text + CHECK constraints**, not Postgres enum types, so adding a value later is one constraint change.
- **Credits** are `numeric(14,4)` (1 credit = ₹1, four decimals for per-second metering). Payments are `numeric(12,2)` rupees.
- **One lead per phone per account** (`uq_leads_account_id_phone`); DNC is unique per account and phone; one number per employee (`employees.number_id` unique).
- **JSONB for fast-moving settings** (employee `draft`, campaign `settings`, call `transcript` / `captured`, lead `fields`) until a phase needs to query or constrain them. Later phases add columns through new migrations.
- **Deletes**: account delete cascades to its data; calls keep their row when an employee, lead or campaign is deleted (`SET NULL`).
- **Webhook secrets** are stored as plaintext because signing needs them back; B12 decides on encryption at rest.

## Auth behaviour

- Email is normalised to lowercase and unique case-insensitively (`uq_users_email_lower`); duplicate signup → 409.
- Wrong password and unknown email return the same 401 and cost the same argon2 verify (dummy hash), so emails can't be enumerated by response or timing.
- Tokens carry `sub`, `iat`, `exp` only; the user and role are loaded from the database on each request, so a role change or deleted user takes effect immediately.
- Rejected: expired, wrong-secret, `alg: none`, tampered and garbage tokens; tokens of deleted users.
- `AXON_JWT_SECRET` unset or shorter than 32 characters → signup and login answer `503 auth_not_configured` (`missing_keys: ["AXON_JWT_SECRET"]`) and nothing is written.
- Making a platform admin: no endpoint yet (B13 builds the admin console). Promote an existing user with
  `UPDATE users SET is_platform_admin = true WHERE email = '<email>';`

## Decisions

- Libraries for the stack's "argon2 + JWT": `argon2-cffi` and `PyJWT` (plus `alembic`, listed in BUILD_PLAN §2).
- Migrations run as their own Compose service, not inside the API process, so several API replicas never race on `alembic upgrade`.
- Database tests use a real Postgres and never fakes. Locally they skip without `AXON_TEST_DATABASE_URL`; in CI a missing URL fails the run.
- Deferred, with the phase that owns it: login and signup rate limiting (B14), token revocation on password change (B13), Google sign-in (later plug), password reset (needs the email provider, B6), API key usage (B12), wallet ledger idempotency and row locking (B7).

## How to run

```bash
docker compose -f deploy/docker-compose.yml up -d postgres redis
uv run alembic -c services/api/alembic.ini upgrade head
AXON_TEST_DATABASE_URL=postgresql+asyncpg://axon:axon@localhost:5432/postgres uv run pytest
uv run python scripts/compose_smoke.py
```

(On Windows PowerShell set the variable with `$env:AXON_TEST_DATABASE_URL = "..."` first.)
