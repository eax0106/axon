# F2 — Sign-up, sign-in, account basics

Branch `phase/f2-auth`.

## What was built

- **Auth screens** share one layout: the brand story on the left (eyebrow, 60 px Manrope line whose mint word rebuilds letter by letter: "Your AI employee never sleeps. / forgets a lead. / keeps a caller waiting.", and a hairline list of facts), the form on the right; stacked on a phone. The cycling stops under reduced motion and screen readers get one static sentence.
- **Sign-up**: business name (any script), email, password. Empty, malformed and short values are caught in place before a round trip; a taken email (409) and the sign-up limit (429) are shown next to the field or form. On success the owner lands in the app signed in.
- **Sign-in**: wrong password (401), the 15-minute limit (429) and validation (422) in plain words; returns to the page the user first asked for.
- **Sign-out** from the rail or the palette (one `session.set(null)`).
- **Account page** (`/account`, in the rail and ⌘K): who is signed in, and the owner's phone. Verification: a 10-digit Indian mobile is checked in the browser, then the API calls it and reads out a code; the code step shows the API's real expiry; wrong code, too many tries, "buy a number first", busy channels and do-not-call come back from the API next to the field; a missing carrier key shows the "Connect Vobiz" state. Once verified the number shows with a Verified tag.
- **Shared `Field` and `SubmitButton`** (`ui/Field.tsx`): 48 px inputs with label, hint, error (`aria-invalid`, `aria-describedby`) and an optional prefix.
- **API**: `/accounts/me` also returns `account.owner_phone` ("" until verified), so the app can show the verified phone after a reload.
- **Fix from F1**: queries no longer retry a 503 `provider_not_configured`.

## Not built, and why

- **Terms acceptance at sign-up.** The API (`/account/terms`) is ready, but there is no terms text or version yet (owner, legal). A checkbox that records consent to a text that doesn't exist would be fake, so it waits for the text.
- **The code-entry step end to end.** It needs a real carrier call (Vobiz keys and a bought number, Track 3). The e2e test covers everything up to the API's 503.

## How to run

As F1 (`docs/phases/f1.md`). e2e: `pnpm --filter web e2e` against the Compose stack; it now has `e2e/auth.spec.ts`. Note the API's sign-up limit is 10 an hour per address, so many local e2e runs in an hour hit 429.
