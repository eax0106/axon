Branch `phase/b3-speech-llm-adapters`. Builder: axon-builder-sonnet, with the `ponytail` and `unlazy` skills loaded at the start of the phase. Gate ledger: `.unlazy/axon/gates/b3.md` (untracked, in the builder worktree).

## What was built

| Vendor adapter | Where | Health check (real vendor call) |
|---|---|---|
| STT / TTS / LLM `sarvam` | `services/api/app/providers/speech/sarvam.py` | `POST https://api.sarvam.ai/text-lid`, header `api-subscription-key` (see open items) |
| STT / TTS `smallest` | `speech/smallest.py` | `GET https://api.smallest.ai/waves/v1/lightning-v3.1/get_voices`, `Authorization: Bearer` |
| TTS `cartesia` (Premium) | `speech/cartesia.py` | `GET https://api.cartesia.ai/voices?limit=1`, `Authorization: Bearer`, `Cartesia-Version: 2026-08-14`; reports `unhealthy` naming `CARTESIA_VOICE_HI` / `_TE` while either is unset |
| LLM `gemini` | `speech/gemini.py` | `GET https://generativelanguage.googleapis.com/v1beta/models?pageSize=1`, `x-goog-api-key` |

| Engine service (`services/engine/engine/services.py`, table `SERVICES`) | Pipecat class | Model / voice |
|---|---|---|
| STT sarvam | `SarvamSTTService`, mode `codemix` | `saaras:v4` |
| STT smallest | `SmallestSTTService` (Pulse) | default |
| TTS sarvam (Value) | `SarvamTTSService` | `bulbul:v3`, voice `shubh` |
| TTS smallest (Standard) | `SmallestTTSService` | `lightning_v3.1`, voices `srihari` (te), `devansh` (hi), `avery` (en) |
| TTS cartesia (Premium) | `CartesiaTTSService` | `sonic-3.6`, voice from `CARTESIA_VOICE_<LANG>` (English default Skylar) |
| LLM gemini | `GoogleLLMService` | `gemini-2.5-flash`, or `AXON_GEMINI_MODEL` |
| LLM sarvam | `SarvamLLMService` | `sarvam-105b`, `max_tokens=1500` |

- **Split of responsibilities:** adapters in the API package know keys and health only (what `/admin/providers` needs). The engine alone imports Pipecat; `SERVICES` is keyed like `registry.ADAPTERS`, and `engine.legs.voice_legs` looks the service up there. A registered vendor without an entry answers `503 provider_not_configured`.
- **Interfaces:** `SpeechToTextProvider`, `LLMProvider`, `TextToSpeechProvider` in `providers/base.py`. `ProviderNotConfiguredError` lives in `base.py` too (the adapters need it and the registry imports them).
- **Voice tiers:** `TIER_TTS` is keyed by `models.VoiceTier`: Value = Sarvam, Standard = Smallest, Premium = Cartesia. `tts_for_tier(tier)` returns the adapter; `voice_legs(language, tier=None)` resolves the three legs once, with the tier choosing the TTS vendor (else the selected TTS, default Sarvam). B4 stores the tier on the employee and passes it in.
- **Languages:** `te`, `hi`, `en`; anything else raises `ValueError`.
- **Contract tests (all `requires_keys`, skipped now):** `services/api/tests/test_speech_contract.py` runs each adapter's health call. `services/engine/engine_tests/test_speech_contract.py` drives each real Pipecat service in a minimal pipeline for te, hi and en: TTS synthesizes a sentence and must return audio frames; STT transcribes a committed clip (`engine_tests/fixtures/hello_{te,hi,en}.wav`, 16 kHz mono, generated with macOS `say`) and must return a non-empty transcript; LLM completes one prompt and must return text. These confirm the model ids, voice ids and language support that a health check cannot. The harness itself (`run_until`) is pinned offline with a stand-in processor.

## Decisions

- **Pipecat's own services, no hand-written streaming.** Pipecat 1.14 ships services for exactly these vendors.
- **Dependencies:** no new package. `pipecat-ai` gained the extras `google` (google-genai) and `sarvam` (sarvamai 0.1.28, pinned by Pipecat) on the engine only, plus their transitive packages. `httpx` does the health calls.
- **Cartesia Hindi and Telugu voices:** Cartesia's docs list only English voice ids. Hindi and Telugu need `CARTESIA_VOICE_HI` / `CARTESIA_VOICE_TE`; without them the Premium tier answers `503 provider_not_configured` naming the variable, and `/admin/providers` shows Cartesia `unhealthy` with the same names, instead of guessing a voice.
- **Gemini model:** BUILD_PLAN says Gemini 2.5 Flash. Google's docs say new keys may be refused on 2.5, so `AXON_GEMINI_MODEL` switches model with no code change; the contract run shows which model the key accepts.
- **Sarvam health:** no read-only endpoint is documented, so health posts a one-word language-id request (a bad key answers 403). Admin-only behind the 30 s health cache. If the contract run shows it is billed, raise the cache TTL for Sarvam.
- **Failover** between vendors mid-call is B13; nothing here switches vendors on error.

## Carry-forward

- **B4:** voice ids are fixed in `engine/services.py` (Sarvam, Smallest) or read from env (Cartesia). The B4 voice picker should take them from the `voices` table, seeded per tier and language; these constants then go away.
- **B13:** a Premium call with no Hindi or Telugu voice is the "Premium falls back to Value at the Value price" case. Failover must treat a `ProviderNotConfiguredError` at service-build time as unhealthy.
