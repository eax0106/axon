# B3 — Speech and LLM adapters

Branch `phase/b3-speech-llm-adapters`. Builder: axon-builder-sonnet, with the `ponytail` and `unlazy` skills loaded at the start of the phase. Gate ledger: `.unlazy/axon/gates/b3.md` (untracked, in the builder worktree).

## What was built

| Adapter | Where | Pipecat service it builds | Health check (real vendor call) |
|---|---|---|---|
| STT `sarvam` | `services/api/app/providers/speech/sarvam.py` | `SarvamSTTService`, model `saaras:v4`, mode `codemix` | `POST https://api.sarvam.ai/text-lid`, header `api-subscription-key` (see open items) |
| TTS `sarvam` (Value) | same | `SarvamTTSService`, `bulbul:v3`, voice `shubh` | same |
| LLM `sarvam` | same | `SarvamLLMService`, `sarvam-105b`, `max_tokens=1500` | same |
| STT `smallest` | `speech/smallest.py` | `SmallestSTTService` (Pulse) | `GET https://api.smallest.ai/waves/v1/lightning-v3.1/get_voices`, `Authorization: Bearer` |
| TTS `smallest` (Standard) | same | `SmallestTTSService`, `lightning_v3.1`, voices `srihari` (te), `devansh` (hi), `avery` (en) | same |
| TTS `cartesia` (Premium) | `speech/cartesia.py` | `CartesiaTTSService`, `sonic-3.6` | `GET https://api.cartesia.ai/voices?limit=1`, `Authorization: Bearer`, `Cartesia-Version: 2026-08-14` |
| LLM `gemini` | `speech/gemini.py` | `GoogleLLMService`, `gemini-2.5-flash` (env `AXON_GEMINI_MODEL` overrides) | `GET https://generativelanguage.googleapis.com/v1beta/models?pageSize=1`, `x-goog-api-key` |

- **Interfaces:** `SpeechToTextProvider`, `LLMProvider`, `TextToSpeechProvider` in `providers/base.py`. `ProviderNotConfiguredError` moved to `base.py` (the adapters need it and the registry imports them); import it from there.
- **Registry:** all seven adapters are in `ADAPTERS`; `/admin/providers` now health-checks them with the real vendor once keys are set.
- **Voice tiers:** `TIER_TTS = {value: sarvam, standard: smallest, premium: cartesia}` and `tts_for_tier(tier)` in `registry.py`. `engine.legs.voice_legs(language, tier=None)` takes the TTS vendor from the tier; without a tier it uses the selected TTS (`AXON_TTS_PROVIDER`, default Sarvam). B4 stores the tier on the employee and passes it in.
- **Languages:** `te`, `hi`, `en`. Anything else raises `ValueError`.
- **Pipecat imports are late** (inside `pipecat_service`), so the API image, which has no Pipecat, still imports the adapters.
- **Shared code:** `speech/common.py` holds the language check and the one health request, so each adapter is its endpoint, headers and service.

## Decisions

- **Pipecat's own services, no hand-written streaming.** Pipecat 1.14 ships Sarvam, Smallest, Cartesia and Gemini services for exactly these vendors.
- **Dependencies:** no new package. `pipecat-ai` gained the extras `google` (google-genai) and `sarvam` (sarvamai 0.1.28, which Pipecat pins), plus their transitive packages. `httpx` does the health calls.
- **Cartesia Hindi and Telugu voices:** Cartesia's docs list only English voice ids (the default is Skylar). Hindi and Telugu need `CARTESIA_VOICE_HI` / `CARTESIA_VOICE_TE`; without them the Premium tier answers `503 provider_not_configured` naming the variable instead of guessing a voice.
- **Gemini model:** BUILD_PLAN says Gemini 2.5 Flash. Google's docs say new keys may be refused on 2.5, so `AXON_GEMINI_MODEL` switches model with no code change.
- **Sarvam health:** Sarvam documents no read-only endpoint. Health posts a one-word language-id request (a bad key answers 403).
- **Failover** between vendors mid-call is B13; nothing here switches vendors on error.

- Pick Cartesia Hindi and Telugu voices; confirm the Smallest voice choices sound right (`srihari`, `devansh`, `avery`).
- Confirm the chosen Gemini model is available to the key.
- Native-speaker quality checks in Telugu, Hindi and English are a Track 3 gate.
