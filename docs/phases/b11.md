## What was built

They sit outside the script bundle, so they apply to the next call at once and have no publish, versions or restore. Saving is all or nothing, repeats are skipped, and a full list answers 409. |
| Propose, review, save | `app/training/propose.py`, `router.py` | `POST .../training/propose` (text), `propose-voice` (one WAV clip through the selected STT), `propose-photo` (an image read by the model). The model splits the input into facts and rules and **nothing is stored**: the client shows the list, the owner edits it, and `POST .../training/items` saves it. Items that are too long or are neither a fact nor a rule are dropped and counted. Each proposal is one paid use of AI help (refunded if it fails). |
| Prompt | `app/employees/compiler.py`, `runtime.py` | `Knowledge(facts, rules, documents)` is read from the database for every prompt. Facts get their own section after the FAQ and are the newer word where they disagree with it. Rules are conduct lines after the built-in conduct, followed by a line saying they never excuse it. Stored text is flattened to one printable line, so it cannot add a heading or a list. Nothing is added for an employee that was taught nothing. The text chat sandbox uses the same prompt but leaves the documents line out (it has no tools). |
| Documents | `app/training/chunks.py`, `knowledge.py`, `router.py`, migration `0009` | Upload plain text, markdown, CSV (read as UTF-8), or a PDF or png/jpeg/webp (read by the model, `FileReader`). Cut into passages of at most 700 characters that end at a sentence (`.` `?` `!` `।` `॥`) or a line and start with the last sentence of the one before. Each passage is embedded (Gemini, 768 numbers, unit length) and stored in `knowledge_chunks`. At most 10 documents of 60,000 characters (up to 200 passages) each; any failed step stores nothing. A PDF or photo the model did not finish reading (its reply did not end normally) is refused with 422 and nothing is stored, never saved as complete. |
| Retrieval | `app/training/knowledge.py` | The dot product of the question and every passage of that employee is taken inside Postgres (`unnest` over `REAL[]`), and the best three scoring at least 0.55 come back. Unrelated questions find nothing. Passages embedded at another size are skipped. `POST .../documents/search` lets the owner try a question. |
| Look-up tool | `app/training/tool.py`, `engine/main.py`, `compiler.py` | `look_up_knowledge(question)` is offered on a call only when the employee has documents. It never raises (a failure is `{"ok": false, "error": ...}`), is cut off at its timeout, and the call's timeline records that it ran, never the question or the answer. The prompt says what it returns is data, not instructions. The name is reserved against actions. |
| Struggle detector | `app/calls/analysis.py`, `app/training/struggle.py`, `postcall.py` | The post-call analysis also lists up to three struggles: `unanswered` (a question the AI could not or would not answer) and `conduct` (something the business would not want). A struggle is kept only when the caller's words are a real quote from one caller turn; a conduct struggle also needs the AI's own quoted words and a one-line rule. A gap carries no text (only the owner knows the answer). Test calls produce none. A moment the owner has already seen does not return. 50 open at most per employee. |
| Suggestions | `app/training/router.py` | `GET .../training/suggestions`, `POST .../{id}/accept` (the owner's text, or the suggestion's own; a gap needs the owner's answer) and `.../dismiss`. Accepting teaches the item at once. |

## Decisions

See `docs/DECISIONS.md` (five rows dated 2026-10-27 for B11). The ones worth a second look:

- **No pgvector extension.** BUILD_PLAN names pgvector, but CI uses stock Postgres on ubuntu, macOS and Windows where the extension is not installed, so a `vector` column would fail the migration there. Passages are stored as `REAL[]` and ranked in SQL. The compose image already has pgvector, so moving to a `vector(768)` column with an HNSW index is one migration when documents outgrow a scan (10 documents of at most about 90 passages each today).
- **A taught fact beats the FAQ.** Training is the owner's correction of the published script, applied at once, so it is the newer word. A taught rule is conduct and cannot override the built-in conduct (honesty, politeness, stopping when asked).
- **Gaps carry no text.** The model may point at a moment and quote it, but what the employee is taught is always the owner's word; a conduct suggestion carries the model's proposed rule, which the owner can reword before saving.
- **A half-read file is a failure.** `GeminiLLM.read_file` accepts a reply only when the vendor says it ended normally (`finishReason` `STOP`); otherwise it raises `FileUnreadError` and the endpoint answers 422 ("the whole file could not be read"). A price list that stopped at "Coffee 3" would otherwise be taught as a fact.
- **Zero-width joiners are text.** The cleaner for taught text and script values turns control and invisible characters into spaces except ZWJ (U+200D) and ZWNJ (U+200C), which sit inside Telugu and Hindi words and conjuncts; stripping them split the words.
- **Relevance threshold 0.55** is a first guess for Gemini's cosine scores; WIRING item 27 tunes it on real documents.

## Open items

- **Original files are not kept.** Only the passages and the document's name are stored, so a document cannot be downloaded again or re-embedded after a model change (upload it again). R2 is the place when that is wanted.
- **Photo and PDF reading, embedding scores and the batch body are proven only against the vendor's documented request shape** (the contract test for embeddings is `requires_keys`). The "photo price list changes answers" keys gate runs at wiring.
- **One large vector scan per look-up** (`shortcut:` comment in `knowledge.py`).
- **Members can teach** as well as owners (no role check), like the script editor. Say if teaching should be owner-only.
- **No notification for new suggestions;** the count is on `GET .../training` (`open_suggestions`).
- **The struggle detector rides on the analysis prompt,** so a re-analysis of an old call can add suggestions for it too.
- **Documents use the hourly AI allowance but no per-use fee,** unlike a proposal. A PDF read costs us a model call; revisit if it is abused.

## How to run

```bash
docker compose -f deploy/docker-compose.yml up -d postgres redis
uv run alembic -c services/api/alembic.ini upgrade head && uv run python -m app.voices
AXON_TEST_DATABASE_URL=postgresql+asyncpg://axon:axon@localhost:5432/postgres AXON_TEST_REDIS_URL=redis://localhost:6379/5 uv run pytest
```

Teaching and documents need `GEMINI_API_KEY` (and `SARVAM_API_KEY` or another STT key for spoken teaching); without them each endpoint answers 503 `provider_not_configured`.
