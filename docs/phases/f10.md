# F10 — Training, knowledge, in-call actions

Branch `phase/f10-training`.

## What was built

- **Training** tab (`/employees/:id/training`); unlike the script, it applies to the next call at once:
  - **From real calls**: moments the post-call analysis flagged, with the caller's own words (and the employee's, for conduct), in plain words; write or edit the answer and "Teach this fact/rule", or dismiss. Nothing is taught until accepted.
  - **Teach something new** by typing, speaking (one recording up to 25 s, live waveform) or a photo (png, jpeg, webp). The AI only proposes; the owner reviews every item (edit, switch fact/rule, remove) and saves. Items the API dropped as too long or unclear are counted.
  - **Facts** and **rules** with their limits (60 and 20, 300 characters each): add by hand, edit in place, remove.
  - **Documents** (text, Markdown, CSV, PDF, photo; up to 10): upload, remove (confirmed), and "Try a caller's question" to see which passages would be used.
- **Actions** tab (`/employees/:id/actions`):
  - **Google**: one connection per account, showing which services Google actually granted; connect through consent (finished on return) or disconnect.
  - **During the call**: up to 10 actions, opt-in: book in Google Calendar, look up or write to a Google Sheet, call your own API (method, https address, bearer or header secret, parameters, timeout), send an approved WhatsApp template. Each has a name the model calls and when to use it; problems are named before saving (`lib/actions.ts`, unit-tested). Saved actions go live with "Apply to live calls", like the script. Secrets are never shown back (the masked value keeps the stored one). A test console runs a saved action with sample JSON and shows the API's answer.
  - **Send each result to your system**: the employee's result webhook (https address, trigger: every connected call / skip voicemail / voicemail only, optional signing secret never shown back), test send, remove.

## Also in this PR

- **CI**: the compose job's throwaway stack now runs with `AXON_AUTH_RATE_LIMIT=off`. Ten e2e flows sign up eleven accounts from one address, over the 10-an-hour limit, so the tenth flow sat on the sign-in page. The limits keep their own backend tests; production is unchanged.

## How to run

As F1. `e2e/training.spec.ts`: teaching without a key shows the provider state; a fact and a rule added, edited, removed with the counts following; a document upload shows the embedding provider state and stores nothing; an HTTP action with a secret saved, the secret masked (checked through the API), the publish bar shown, the test console answering; the result webhook saved with its trigger and a masked secret; axe clean at desktop and 375 px. All 10 e2e specs pass. Locally the e2e stack needs `AXON_AUTH_RATE_LIMIT=off` too (a Compose override for the api service).
