# F4 — Test calls and the live-call view

Branch `phase/f4-live`.

## What was built

- **Try it** tab on every employee:
  - **Chat**: type as a caller would, against the draft script (`/employees/{id}/chat`). Nothing stored or billed.
  - **Talk in the browser**: `/employees/{id}/web-test-call` gives a ticket; the browser opens the engine's `/web/stream` and speaks its protocol (`lib/webcall.ts`): 16 kHz PCM16 base64 `media` up, `playAudio` down and scheduled gap-free, `clearAudio` stops queued speech when the caller barges in, and each `checkpoint` is answered with `playedStream` once the audio before it has really played, so the goodbye is never cut off.
  - **Ring my phone**: `/employees/{id}/test-call` to the verified owner phone; a link to Account when no phone is verified yet.
  Without keys each mode shows the "Connect …" state for the provider it needs.
- **Live-call view** (`pages/calls/LiveView.tsx`, also at `/calls/:id/live`):
  - The **orb** (react-three-fiber, a noise-displaced sphere in the accent token) swells with the real audio level in a browser call, and breathes with the call's stage on phone calls. WebGL loads only on these screens (its own 244 KB gzip chunk); it renders on demand at 60 fps while there is sound, 30 when quiet, and not at all on a hidden tab; under reduced motion it is a still glow and no WebGL loads.
  - **Stepper** RINGING · LISTENING · THINKING · SPEAKING · DONE; the mint dot glides (300 ms) as engine events arrive.
  - **Streaming transcript**: the employee's streamed words join into one turn with a caret while speaking; Telugu, Hindi and English kept as sent.
  - Pulsing "On a call" state, quiet notes for tools used and provider switches, and the end reason.
  - A call opened after it ended shows its stored transcript and "Call ended" instead of waiting forever.
- `lib/live.ts`: a pure reducer from engine events (`engine/events.py`, `call.py`) to view state, unit-tested, and `useLiveCall` over the API's `/calls/{id}/live` WebSocket.

## Fixes found on the way

- **The API image had no WebSocket library**, so `GET /calls/{id}/live` answered 404 behind uvicorn (uvicorn logged "No supported WebSocket library detected"). `websockets` (already in the lock through the engine) is now an API dependency. This was a Track 1 gap: the endpoint was only ever tested through FastAPI's TestClient.
- **`scrollIntoView` returns a promise in current Chrome**; an effect written as an expression returned it and React called it as a cleanup, which crashed the page and closed the socket. Effects in the app now use braces.
- Inline text links are underlined (axe `link-in-text-block`).

## Follow-up for the backend (not changed here)

The live WebSocket carries the user's 12-hour session token in its URL (browsers cannot set headers on a WebSocket), and both uvicorn and nginx write request URLs to their access logs, so tokens land in logs. A short-lived single-use ticket for the live socket, like the engine's web-call ticket, would fix it. Worth a small backend PR before launch.

## Not here

Captured fields flying out of the transcript (DESIGN_DIRECTION §6.3): the engine publishes no live capture event; captured fields come from the post-call analysis (shown in F6). The "answering now" inbound state reuses this view in F9.

## How to run

As F1. e2e: `pnpm --filter web e2e` now includes `e2e/live.spec.ts`, which inserts a call row with `psql` and publishes events on its Redis channel exactly as the engine does, through `docker compose exec` (honours `COMPOSE_PROJECT_NAME`).
