## Decisions

- **A call row is the queue entry.** `queued` + `scheduled_for` is waiting; `queued` + NULL is held until a redial; the next attempt is a new row (`attempt` + 1), so every attempt keeps its own record for B6 and B7.
- **Outcomes come from the carrier's record, not the callback.** Vobiz signs only the callback URL and a nonce (never the body), and its hangup callback says `completed` for every ending. So the callback only names the call; busy, no answer and answered come from the authenticated CDR (`billsec > 0` = answered; `USER_BUSY` = busy; `NO_ANSWER` / `ORIGINATOR_CANCEL` = no answer; the rest failed). A call the carrier never reports on is failed after 15 minutes so the lead is not lost.
- **Default window 9 AM to 9 PM**, inside the hard 6 AM–10 PM limit the owner can widen it to. TRAI's TCCCPR schedule marks 21:00–24:00 and 00:00–10:00 bands default-off for promotional calls, so the safest default is narrower than the hard limit. Legal sign-off on the windows is still open (DECISIONS).
- **Fixed IST, no account time zone.** India has no daylight saving and named zones need the `tzdata` package on Windows (not in BUILD_PLAN §2). An owner-settable offset would have moved the hard limit, so there is no setter; `rules` still takes the offset as a parameter for tests. Upgrade path: IANA names + `tzdata` when another market arrives.
- **An unknown outcome holds the lead, never retries it.** The dial-request id and the call's own id can differ, so the callback may name either; the call is looked up by both and the carrier's record by the call id (then the request id). If after 15 minutes there is no callback, no record and the call is not live, the attempt is closed as failed and the next attempt is queued *held*: someone who may have answered is not redialled on a guess, and the lead is not lost. A carrier error while dialing that is not a plain refusal (a timeout) holds the same way.
- **Settling is under a row lock**, so a callback and the reaper cannot both queue the next attempt.
- **One bad source never blocks the others:** a failing Meta lead is logged as rejected in the owner's intake log and the batch continues; a failing Sheets connection is logged and skipped.
- **Connect-time checks:** a Meta form can be connected only with a token that can read it (and a conflict answers the same 409 whoever holds the form); the Google consent `state` is a signed, short-lived ticket bound to the user and employee.
- **DNC is enforced for Instant** (intake rejects it, the dialer re-checks it before every dial, redial refuses it). Outpero does not.
- **Wrong-secret attempts are not logged**, only refused.
- **No new dependency.** `axon-worker` now depends on the workspace package `axon-api`.

## Open items

- Real-call confirmation of Vobiz's callback format (form vs JSON; the docs contradict themselves), the CDR fields, and that `from` must be a number on the account (WIRING_CHECKLIST #20). Contract tests are tagged `requires_keys`.
- Meta: app review and the `leads_retrieval` permission; page tokens are entered per form by hand until an OAuth connect flow is built (WIRING_CHECKLIST #19).
- Google: the OAuth client must be a verified app for non-test users (WIRING_CHECKLIST #11).
- The engine does not yet mark a call `in_progress` or write duration; Vobiz's CDR sets the final status here, B6 owns the rest of the call record.
- Redial and one-off calls apply the window and DNC but not the purpose rule table (B7 replaces `policy.check_dial`).

## Carry-forward

- **B6:** the engine writes `in_progress` and duration; today the dialer sets `ringing` and the final status from the carrier's record.
- **B7:** the rule table replaces `policy.check_dial`.
- **B12 / B13:** encrypt the Meta and Google tokens at rest; move the callback nonce store to Redis when the API scales out; `GIVE_UP_AFTER` must exceed the longest call; pause the dialer after repeated `dial_failed`.
- **Sheets cursor** is a row count: append-only sheets only (noted in code).
- Strict/relaxed Instant policy (DECISIONS) waits for the legal opinion; the hook is in place.
- B13: carrier outage handling for the dialer (pause on repeated `dial_failed`).

## How to run

```bash
docker compose -f deploy/docker-compose.yml up -d postgres redis
uv run alembic -c services/api/alembic.ini upgrade head && uv run python -m app.voices
AXON_TEST_DATABASE_URL=postgresql+asyncpg://axon:axon@localhost:5432/postgres AXON_TEST_REDIS_URL=redis://localhost:6379/5 uv run pytest
uv run --env-file .env --directory services/worker python -m arq worker.main.WorkerSettings   # the dialer
```

The dialer needs `VOBIZ_AUTH_ID`, `VOBIZ_AUTH_TOKEN`, `AXON_ENGINE_PUBLIC_URL` and `AXON_API_PUBLIC_URL` (https). Without them it logs why and idles.
