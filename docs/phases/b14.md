## Decisions

See `docs/DECISIONS.md` (rows dated 2026-10-28 for B14). The ones worth a second look:

- **Count first, then check.** A check-then-count limit lets 30 parallel guesses through before the first is counted. `INCR` first (in a transaction with the `SET NX EX` that starts the window) closes that; a test fires 30 guesses at once and expects exactly 10 attempts.
- **The limit is keyed on the typed email, not on the account**, so it cannot be used to learn which emails exist.
- **Terms acceptance is stored, the terms are not.** The text and its version belong to the owner (legal); the endpoint takes any version string.
- **F5 and F6 are the owner's.** Encrypting stored secrets adds `cryptography` as a direct dependency (already in `uv.lock`) and a key to look after; a second factor for staff is a new feature.
- **Backups are logical dumps.** Good for small and medium databases and for the restore drill; a managed Postgres with point-in-time recovery is better in production.

## How to run

```bash
uv run python scripts/backup.py dump --dir backups --keep 14
uv run python scripts/load_test.py --base-url http://localhost:8000 --users 50 --rounds 20   # server needs AXON_AUTH_RATE_LIMIT=off
AXON_TEST_DATABASE_URL=postgresql+asyncpg://axon:axon@localhost:5432/postgres AXON_TEST_REDIS_URL=redis://localhost:6379/5 uv run pytest
```

New optional settings: `AXON_AUTH_RATE_LIMIT` (`off` for load tests only) and uvicorn's `FORWARDED_ALLOW_IPS` behind a proxy. New migration `0012_terms_acceptance`. No new keys or dependencies. Tests that dump and restore need the PostgreSQL client tools (`pg_dump`, `pg_restore`, `psql`); they skip locally without them and fail in CI.
