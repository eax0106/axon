## `/admin/providers` and missing keys

`GET /admin/providers` returns one row per vendor:

```json
{"kind": "stt", "name": "sarvam", "selected": true, "status": "missing_key",
 "missing_keys": ["SARVAM_API_KEY"], "error": null}
```

- `missing_key`: any of its keys is unset or empty.
- `configured`: keys present, and the adapter's `health()` passed (or no adapter is built yet).
- `unhealthy`: keys present but `health()` raised or took over 5 s; `error` holds the reason.

A route that depends on `registry.require(kind)` answers:

```json
503 {"error": "provider_not_configured", "kind": "stt", "provider": "sarvam",
     "missing_keys": ["SARVAM_API_KEY"], "detail": "stt provider 'sarvam' needs SARVAM_API_KEY"}
```

The same 503 is returned when the selection names an unknown vendor (`missing_keys` = the `AXON_<KIND>_PROVIDER` variable) or when keys exist but the adapter isn't built yet.

## Decisions

- **No adapters in B0.** The registry knows vendors and keys; the adapter classes come with B2/B3 onwards. Nothing pretends to work: without an adapter, `require()` still answers 503.
- **Settings use the standard library**, not pydantic-settings, which isn't in BUILD_PLAN §2.
- **Email has no vendor yet.** `ProviderKind.EMAIL` exists with no vendors, so `/admin/providers` lists none until B6 picks one.
- **`/admin/providers` is unauthenticated in B0.** It shows key names and status, never values. B1 adds auth and roles and must put admin routes behind them.
- **Tests don't rely on editable installs.** On this macOS machine uv marks `.venv` hidden and Python 3.12 skips hidden `.pth` files, so `pytest`'s `pythonpath` and mypy's `mypy_path` name the source roots directly.
- **Layout.** `services/engine` (B2), `apps/web` (Track 2) and `packages/contracts` (B12) are created by the phases that fill them.
- **Host ports** default to 8000 / 5432 / 6379 and move with `AXON_API_PORT`, `AXON_PG_PORT`, `AXON_REDIS_PORT` if a local Postgres or Redis already uses them.
