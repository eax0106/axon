# F13 — Help centre, integration guides, final parity and quality pass

Branch `phase/f13-help`.

## What was built

- **Help centre** (`/help`, its own lazy chunk; rail and ⌘K "Help"): searchable articles in our own words, grouped as Start here (first employee, credits), Calling (Instant, Bulk, Inbound, do-not-call), Lead sources (website POST, Meta Lead Ads, Google Sheets), Automation tools (Zapier, Make, n8n, Pabbly Connect), Developers (REST API, webhooks with signature checking in Node and Python) and Account (support). Each article links to the related ones and to Support.
- **Guides use real values**: the lead-source and tool guides show the reader's own lead URL and secret header from one of their Instant employees (a picker when there are several), and say plainly when there is no Instant employee yet. The secret itself stays behind Reveal on the Instant tab. The API guide uses this deployment's address. The signature code was run against the API's own signer (valid body accepted, changed body refused).
- **Empty states** for employees and campaigns use the site's cycling headline (shared `ui/CyclingLine`, also used by sign-in). Letters wrap only between words; reduced motion keeps the first phrase still; screen readers get one sentence.
- Developers page now links to the guides.

## Quality pass

- **Lighthouse** (mobile preset, 4× CPU slowdown, against the Compose stack, signed in): dashboard 97 / 100, call list 100 / 100, live call 93 / 100 (performance / accessibility). Fixes it took:
  - nginx served JS and CSS uncompressed: `gzip` on for CSS, JS, JSON and SVG (`deploy/nginx.conf`).
  - Dashboard layout shift of 0.37: the first-run checklist appeared after loading and pushed the dashboard down. It now holds its room with a skeleton while loading, and once every step is done the browser remembers not to reserve room again.
  - Live call blocking time: the WebGL orb now starts when the browser is idle (the still glow shows until then), and its sphere uses a quarter of the triangles (no visible difference at its size).
- **End-to-end**: 15 Playwright tests pass against Compose, including the new `e2e/help.spec.ts` (search, a guide without and then with an Instant employee showing the real lead URL and header, the webhook guide; axe at desktop and 375 px). Every spec runs axe; the specs drive the app by role and label, which is the keyboard path.
- **PARITY.md**: the guides row and the dashboard/admin UI row are ticked. The only open row is the five licensed ambience loops, an owner-supplied asset (WIRING_CHECKLIST #17), not UI.

Lighthouse is not a project dependency; it was run from a scratch folder: install `lighthouse@12.8.2` there, start Chromium with a remote-debugging port and a signed-in profile, and point Lighthouse at `/`, `/calls` and `/calls/<id>/live` with storage reset off.

## Also in this PR

- **Three backend tests started failing on 2 November 2026** (every OS, also on `main`): they pin the suite's clock to 05:30 UTC that day while the API stamps resends and checks a campaign's start time with the real clock. Once real time passed 05:30 UTC, a resend was "due" after the test's clock and a start time an hour after it was already past. The tests now anchor those steps on whichever is later, the fixed clock or the real one; the resend test checks the resend by its delivery id, since the other delivery's retry can fall due at the same moment. No product code changed. Other tests pin times on the same day; the full backend suite passes after both of them.
