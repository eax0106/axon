# B6 — Post-call and data views

Branch `phase/b6-post-call-data`. Builder: axon-builder-sonnet, with the `caveman`, `ponytail` and `unlazy` skills loaded at the start of the phase. Gate ledger: `.unlazy/axon/gates/b6.md` (untracked, in the builder worktree).

## What was built

| Area | Where | Notes |
|---|---|---|
| Call records (B4/B5 carry-over) | `services/engine/engine/records.py`, `call.py`, `main.py` | The engine now writes the call's own row: pickup moves it to `in_progress` (`answered_at`), and at the end it stores the transcript, duration, final status (`completed`, or `failed` if the pipeline errored), recording key, stored events, and marks it `analysis_status = pending` (test calls: none). `TranscriptBuilder` turns the live events into turns (the agent's words are gathered until it stops, is interrupted, or the caller speaks). A carrier call only touches a row that waits for that carrier call (by the dial-request id or the call's own id) or has no carrier id yet. **Status, end time and duration change only while the call is open; the transcript, recording key, events and the go-ahead for analysis are written whatever the status**, because Vobiz's callback usually settles the call first (the engine is still uploading the recording) and the engine's data would otherwise be lost. |
| Abandoned test rows (B4 carry-over) | `engine/main.py`, `calls/postcall.py` | A web call whose setup fails after the ticket was claimed is closed `failed` with a `setup_failed` event; the worker also reaps test calls left `queued` for 10 minutes (unused ticket) or `in_progress` for 90 minutes. |
| Post-call job | `app/calls/postcall.py`, worker `post_call_tick` (every 10 s) | Claims `pending` calls (marks them `analysing` and commits, under `FOR UPDATE SKIP LOCKED`; a claim older than 10 minutes is taken again), then for each call reads its data, asks the selected LLM through the registry **with no lock held**, and writes the result in its own transaction. One crashing call is marked `failed` and the rest go on. and writes summary, sentiment, outcome and the **captured fields** (B4's declared values). Without an LLM key the calls are marked `skipped` (never filled in); a malformed or failed reply marks them `failed` with the error type. `POST /calls/{id}/reanalyze` puts a skipped or failed one back. |
| Nothing invented | `app/calls/analysis.py` | The model must quote the words behind every captured value, a callback time and a do-not-call request. A quote counts only if it is at least 6 characters or 2 words ("yes", "no", "ok" prove nothing) **and sits inside one single turn the caller spoke** (never an agent line, a label, or words stitched from several turns). Quotes are compared after case-folding and turning only punctuation and symbols into spaces; combining marks (the vowel signs and virama of Hindi and Telugu) stay in their words, so a real Hindi or Telugu quote matches and a consonant-only fragment does not. A captured value must also be made only of the words of its quote: the caller's words, not a rewrite ("5 lakh" for "five lakh" is dropped). Anything else makes the value null; undeclared fields are dropped; outcomes and sentiments outside the allowed lists become null; a call where the caller said nothing is `no_conversation` and the model is not asked. |
| Callback scheduling | `postcall._schedule_callback` | "Call me at 6": the model gets the time in IST and returns an ISO time with the quote; it must be in the future and within 14 days. It becomes a queued call (`is_callback`) on the employee's channel, moved into the calling window; one callback at a time per lead; a notification says so. Instant callbacks are dialed by the B5 dialer; Bulk and Inbound pick them up in B8 and B9. |
| Auto-DNC | `postcall._add_to_dnc` | A caller's own words asking not to be called again add the number to the do-not-call list (source `caller_request`), cancel anything waiting for it, skip any callback, and raise an "auto-DNC confirmation" notification. The caller's quoted words are stored in the DNC reason and shown in the notification so the owner can judge and undo it. |
| Caller memory | `calls/memory.py`, `employees/compiler.py`, `engine/plan.py` | A short note per lead, written by the same extraction when the account's toggle is on (default on, owner-settable), fenced as notes-not-instructions in the next call's prompt. `DELETE /leads/{id}/memory` and `DELETE /account/caller-memory/data` forget one lead or everyone. |
| Conversations | `calls/conversations.py` | `GET /calls` with filters (outcome, sentiment, employee, channel, campaign, direction, date range, duration, credits, search) and pagination; `GET /calls/export.csv` with the same filters; remembered filters per user (`/me/filters/conversations`). Test calls are hidden unless asked for. |
| Call detail | same | Transcript, summary, captured fields, timeline (turns merged with stored events), notes, a presigned recording link (`/calls/{id}/recording`), a plain-text share summary (`/calls/{id}/share-text`; nothing is published). |
| Leads | `calls/leads.py` | One per phone per account across channels: table with search and filters, kanban board by the latest call's outcome, detail with calls and notes, rename, CSV export with a column picker (base columns and `field:<name>`). |
| Stats | `calls/stats.py` | `GET /stats/overview` for 7/30/90 days or a custom range: totals, connect / qualify / conversion rates, channel split, connect rate by the Indian hour the call was dialed (not queued) and the best hour (min 5 calls), employee leaderboard, and the share of Instant leads first called within 60 s. Definitions are in the module docstring. |
| Notifications | `calls/notifications.py` | List with unread count, mark one or all read, per account. |
| Object storage | `providers/storage/r2.py` | A real S3-compatible adapter (Cloudflare R2): AWS Signature V4 written with the standard library, `put`, a bucket health check, and presigned GET links. Checked against the examples AWS publishes. Without `S3_*` keys: 503. The engine's recording upload now works once keys exist. |
| CSV safety | `calls/csvsafe.py` | Cells starting with `=`, `+`, `-`, `@`, tab or CR get a leading apostrophe, because names, summaries and lead fields are written by strangers. |
| Schema | `migrations/0004_post_call_and_data.py` | `calls.analysis_status`, `analysis_error`, `is_callback`; `leads.memory`; `accounts.caller_memory`; `users.ui_prefs`; `notes`; indexes for the conversations list and the analysis queue. |

## Decisions

- **The engine records, the worker interprets.** The engine writes only what it saw. A DB poll of `analysis_status = pending` (no queue message between the two) survives an engine crash and needs no extra dependency.
- **Evidence beats instruction.** Telling the model "never guess" is not enough; the quote check is what makes a value defensible. The cost is that a paraphrased quote or a converted value ("5 lakh" for "five lakh") loses a true value (it becomes null), which is the safe direction; the prompt tells the model to copy the caller's words.
- **Outcomes** (our list): interested, not_interested, callback_requested, wrong_number, do_not_call, no_conversation, other. "Qualified" = interested or callback_requested; "converted" = interested. They are definitions, not facts about the business, and are written in the stats module so a number can be checked by hand.
- **Skipped, not failed, without a key**, so the calls can be analysed later with one click or call each (`reanalyze`) once keys arrive.
- **Shares are text, not links.** A public link to a call summary would be a new way to leak personal data; the owner pastes the text where they choose.
- **No new dependency.** SigV4 is about 40 lines of `hmac` and `hashlib`.

## Open items

- Real-use contract tests (`test_postcall_contract.py`) need the LLM keys and an R2 bucket: extraction on a real transcript for Gemini and Sarvam, a signed upload and a presigned read-back.
- Confirm on a real call that Pipecat's `TTSTextFrame` text, as the transcript builder joins it, reads naturally in Telugu and Hindi (word spacing) — Track 3 native-speaker check.
- `credits_charged` stays 0 until B7 meters calls; the conversations credit filter and column work now and fill in then.
- Bulk and Inbound pick up queued `is_callback` calls in B8 and B9.
- Memory text is unverified model output: it is capped, fenced and switchable, but a stricter filter against instruction-like text could be added.
- Carry-forward: B7 bills from the carrier's record; B8/B9 make the dialer claim `is_callback` calls per channel; B13 charges the AI-use fee for analysis and re-analysis (re-analysis already draws on the hourly AI budget).
- Announcements (admin console, B13) and the low-balance alert (B7) are not part of the bell yet.
- Carry-forward (B14): measure the null rate of captured fields in Telugu and Hindi on real calls; the quote rules are strict by design and a high rate means the prompt or the rules need tuning.
- The worker takes 3 calls per tick (3 x the 60 s LLM limit fits inside the 240 s job timeout); a claim left by a crash is retaken after 10 minutes.
- A failed analysis is not retried automatically (use `reanalyze`); an automatic back-off retry is a B13 reliability item.

## How to run

```bash
docker compose -f deploy/docker-compose.yml up -d postgres redis
uv run alembic -c services/api/alembic.ini upgrade head && uv run python -m app.voices
AXON_TEST_DATABASE_URL=postgresql+asyncpg://axon:axon@localhost:5432/postgres AXON_TEST_REDIS_URL=redis://localhost:6379/5 uv run pytest
```

The post-call job runs in the worker (`arq worker.main.WorkerSettings`); it needs an LLM key (Gemini or Sarvam) to analyse and `S3_*` keys to keep recordings.
