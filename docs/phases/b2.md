# B2 — Voice engine

Branch `phase/b2-voice-engine`. Builder: axon-builder-opus, with the `ponytail` and `unlazy` skills loaded. Gate ledger: `.unlazy/axon/gates/b2.md` (untracked, in the builder worktree).

## What was built

| Area | Where | Notes |
|---|---|---|
| Engine service | `services/engine/engine/main.py` | FastAPI app: `POST /vobiz/answer`, WebSocket `/vobiz/stream`, `/healthz`. |
| Vobiz stream protocol | `services/engine/engine/vobiz.py` | Answer XML (`<Stream bidirectional keepCallAlive contentType="audio/x-mulaw;rate=8000">`) and our own `VobizFrameSerializer`: `start` (ids nested in `start`), `media` in (mu-law, or L16 if the stream reports it), `playAudio` out (mu-law 8 kHz), `clearAudio` on barge-in, `checkpoint` after each bot utterance, `playedStream` / `clearedAudio` acks, hang up on end. Written from Vobiz's own protocol docs. |
| Call pipeline | `services/engine/engine/call.py` | Pipecat: transport in → STT → user aggregator (Silero VAD + Smart Turn v3) → LLM → TTS → checkpoints → transport out → recorder → assistant aggregator. Pipeline at 16 kHz; the serializer converts to and from the 8 kHz phone leg. |
| Barge-in | Pipecat interruptions + serializer | Caller speech during bot speech interrupts the bot; the serializer sends `clearAudio` so audio already queued at the carrier is dropped. |
| Sentence splitting | Pipecat's TTS text aggregator | Pipecat's splitter already ends sentences at `।` `॥` `.` `?` `!` and keeps "Dr." and "₹1.5" whole; tests pin it for Telugu, Hindi and English. No splitter of our own. |
| Call-length cap | `CallSettings.max_call_s` | Default 600 s, 10 s–60 min. Ends the call (reason `max_length`). |
| Silence watchdog | `CallSettings.silence_timeout_s` | Caller silent this long after the bot finished speaking → call ends (reason `silence`). |
| Recording | `AudioBufferProcessor` | Two tracks (caller left, bot right) → WAV → `ObjectStorageProvider`. No storage adapter exists yet, so the event `recording_not_stored` says so; nothing pretends to save. |
| Usage meter | `services/engine/engine/events.py` | Duration from first caller audio (pickup), caller audio seconds, LLM prompt / completion tokens, TTS characters → `usage` event. B7 turns it into credits. |
| Live events | engine `events.py` → Redis → API `app/live.py` | Engine publishes `started`, speaking states, `interruption`, `user_transcript`, `bot_text`, recording, `usage`, `ended` on `call:<id>:events`. API WebSocket `/calls/{id}/live?token=` relays them to the call's own account (4401 bad token, 4404 other account), until `ended`. |
| AI legs | `services/engine/engine/legs.py` | STT, LLM and TTS come from the provider registry. An adapter offers `pipecat_service(language)`; B3 builds the real ones. Missing → 503 `provider_not_configured`. |
| Telephony adapter | `services/api/app/providers/telephony/vobiz.py` | Real Vobiz REST: health (list live calls), `is_live`, `hang_up` (DELETE call; 404 = already ended). Registered for `telephony/vobiz`. |
| Interfaces | `services/api/app/providers/base.py` | `TelephonyProvider`, `ObjectStorageProvider`. |
| Compose | `deploy/` | `engine` service on port 8001 (image 715 MB unpacked); one Dockerfile for api, engine and worker. |
| CI | `.github/workflows/ci.yml` | Redis on ubuntu and macos for the live-event tests (no native Redis on Windows runners, so those tests skip there). |

## Safety

- The stream WebSocket URL is public, so a stream is served only if Vobiz confirms the call is live (`is_live`); otherwise it closes with 1008.
- No vendor keys → `/vobiz/answer` answers 503 `provider_not_configured` naming the key, and `/vobiz/stream` closes with 1011. `AXON_ENGINE_PUBLIC_URL` must be an `https://` URL, or answering is also 503.

## Decisions

- **mu-law 8 kHz both ways.** The phone leg is 8 kHz anyway, and mu-law avoids the L16 byte-order ambiguity Vobiz's docs warn about.
- **Pipecat `PipelineTask` / `PipelineRunner`** although deprecated since Pipecat 1.3: the replacement `PipelineWorker` / `WorkerRunner` never returned after the call ended in our tests. Migrate when Pipecat 2.0 removes them.
- **Events are keyed by our `calls.id`** when the answer URL carries `?call=` (set by the dialer in B5 or inbound routing in B9), else by Vobiz's call id.
- **The engine imports the API package** for the provider registry, models and settings, so both use one source of truth.
- **Image size is measured unpacked** (`du` inside the image): `docker image inspect` reports compressed size on Docker Desktop's containerd store and unpacked size elsewhere, which hid that the engine image was 1.16 GB. `UV_NO_CACHE=1` keeps uv's download cache out of every image (engine 1.16 GB → 715 MB). Earlier phase docs quoted the compressed figure.
- **No system prompt yet:** `CallSettings.system_prompt` is compiled from the employee's script in B4.
- New dependencies: `pipecat-ai[local-smart-turn-v3,silero,websocket]` 1.14.0 (Silero VAD and Smart Turn v3.2 models ship inside it, 2.3 MB and 8.7 MB; no separate download); `httpx` is now a runtime dependency of the API (vendor HTTP calls).
- The real-call latency gate (reply under 1 s in Telugu, Hindi and English) needs Vobiz, Sarvam and Gemini keys plus the B3 adapters and B5 dialer; it runs in Track 3.

## How to run

```bash
uv run --env-file .env uvicorn engine.main:app --app-dir services/engine --port 8001
AXON_TEST_DATABASE_URL=postgresql+asyncpg://axon:axon@localhost:5432/postgres AXON_TEST_REDIS_URL=redis://localhost:6379/5 uv run pytest
uv run python scripts/compose_smoke.py
```
