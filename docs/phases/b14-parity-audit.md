`docs/research/2026-10-24-outpero-rebuild-blueprint.md` section 3.2 lists Outpero's non-admin endpoints. Every area is covered by a row above except the ones below, each with the reason. Outpero's own paths are not copied; behaviour is.

|---|---|
| Accept terms | Added in B14: `/account/terms` |
| Redial a call from the conversations list | Instant redial is `POST /employees/{employee_id}/instant/queue/{call_id}/redial`; a one-off call to any number is `POST /employees/{employee_id}/instant/call`. The conversations screen (Track 2) uses these |
| A live calls list | Track 2 reads `GET /calls` and follows each call on `/calls/{call_id}/live`; a campaign has its own live panel |
| Save a campaign's contacts as a list | `POST /contact-lists` and `POST /campaigns/{campaign_id}/contacts/from-list` (B8) |
| Lead breakdown, summary and fields | `GET /leads/board` (counts by outcome) and the export field picker on `GET /leads/export.csv` |
| Separate instant, bulk and call-health stats | `GET /stats/overview` returns the channel split, connect / qualify / conversion, best hour, leaderboard and the 60-second speed; its call-health numbers are on the failover and provider-health admin routes |
| A second carrier (Voicelink) with GST and location KYC | Not built: Stage A uses Vobiz only (DECISIONS) |
| A public config and sign-up status, set-up help, a set-up call | Product copy and flags for the dashboard; Track 2 |
| Voice prompt for the builder | Spoken briefs go through `POST /ai/transcribe-chunk` |
