# F6 — Dashboard, conversations, leads

Branch `phase/f6-data`.

## What was built

- **Overview is the dashboard**: greeting, the first-run checklist (until done), then Performance for 7, 30 or 90 days or a custom range (`/stats/overview`): calls, connect rate, qualified and converted rates; calls by hour of day (placed and connected, best hour in mint; a hidden table carries the same numbers for screen readers); channel split; share of Instant leads called within 60 s; leaderboard (inbound employees show answered calls, since they place none). Charts are hand-drawn SVG in the chart tokens; changing the range keeps the old figures dimmed until the new ones arrive.
- **Conversations** (`/calls`): search plus every filter the API has (outcome, sentiment, employee, channel, direction, dates, talk time, credits, test calls), remembered per user on the server (`/me/filters/conversations`, saved 600 ms after the last change); 50 calls at a time with "Show more"; CSV export of the filtered list.
- **Call detail** (`/calls/:id`): outcome, sentiment, talk time, credits; the summary (or why there is none); captured fields; the recording on request (the storage provider's state when not configured); the transcript as stored, Telugu, Hindi and English with joiners intact; notes (add, delete); "Copy summary to share"; re-analyse; a timeline of the call's milestones and events; "Listen in live" while the call is on.
- **Leads** (`/leads`): table, cards, or by outcome of the latest call (read-only columns: an outcome comes from a call, and the API has no way to set one by hand); search and outcome filter; CSV export with a column picker that includes every field captured on calls; the account's caller-memory switch and "Forget everyone". **Lead detail**: rename, captured details, every call, what the employee remembers (with "Forget this caller"), notes.
- **Command palette** now finds employees (from the cache) and leads and calls (from the API, 250 ms after typing stops).
- Shared `Notes` for calls and leads; `download()` for authenticated CSV exports.

## Plan correction

The plan said the kanban moves a lead with an optimistic update. The API has no field for an owner to change a lead's outcome (it is the latest call's), so the board is read-only. Moving leads by hand would need a backend change.

## How to run

As F1. `e2e/data.spec.ts` writes two finished calls and their leads with `psql` (as the engine and post-call job would) and checks the dashboard against `/stats/overview`, a remembered filter, the call detail with a Hindi ZWJ and a Telugu ZWNJ kept, a note, every leads view, the CSV columns, and palette search.
