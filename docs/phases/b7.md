## Decisions

- **The carrier's record decides the charge.** The call callback is unsigned, so it only moves the call to a state; the CDR `billsec` fetched from the carrier prices it.
- **Unknown beats wrong.** No carrier record means no charge and a `reconcile` flag, not an estimate.
- **Renewal is keyed by period.** The reference includes `renews_on`, so a retry, a top-up recovery and a tick can race without double-charging.
- **The account is locked before the number** everywhere both are touched, so the order is the same on every path.
- **Fail closed on the dial table.** A new purpose, number type or context needs a row before anyone can call.
- **Fixed IST (UTC+5:30)** for the invoice year and statements; no time-zone library added.
- **No new dependency.** HMAC, decimals and the HTTP client already in the lock cover Razorpay, invoices and the OTP.

## Open items

- Real-use contract tests (`test_billing_contract.py`) are tagged `requires_keys` and skip until Razorpay test keys, a Vobiz key and a Resend key exist (WIRING rows 21 to 26).
- The Vobiz KYC paths and the response bodies of the number store are written from the documented shape but unconfirmed against the live API (WIRING rows 21 and 22).
- Confirm on a real call that Vobiz reads the `<Speak>` XML in `en-IN` for the owner-phone code (row 26).
- Launch prices, the GST rate and service code, and the seller name, GSTIN, address and state are configuration the owner has to confirm (row 25).
- The Instant setting stays `strict` until the legal opinion; the `instant` rows are seeded for when it flips.
- The invoice PDF is not rendered; invoices are JSON for the dashboard to draw (B10).
- The renewal tick runs every 10 minutes; a number is released on the first tick after grace ends.

## How to run

```bash
docker compose -f deploy/docker-compose.yml up -d postgres redis
uv run alembic -c services/api/alembic.ini upgrade head && uv run python -m app.voices
AXON_TEST_DATABASE_URL=postgresql+asyncpg://axon:axon@localhost:5432/postgres AXON_TEST_REDIS_URL=redis://localhost:6379/5 uv run pytest
```

The worker (`arq worker.main.WorkerSettings`) runs the billing tick and the renewal tick. Top-ups need the Razorpay keys and a webhook at `{API URL}/webhooks/razorpay`; numbers need the Vobiz keys; alert emails need Resend.
