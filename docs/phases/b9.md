## Decisions

See `docs/DECISIONS.md` (nine rows dated 2026-10-27 for B9): answering and closed hours, the recording notice, opening hours, answering call-backs, the auto call-back rules, messages, transfer and its billing, how an answer URL is believed, and the daily summary.

- **The carrier is the witness.** Vobiz does not sign its answer-URL requests (nothing in its documentation), so a request is believed only when the carrier itself lists that call as live. A forged request leaves no row and holds no channel.
- **A refusal is a record.** A call we cannot take is saved with its reason and shows in Conversations and in the missed list; it is never billed.
- **A transfer must not drop the caller.** Our end of the stream closes without hanging up; if the carrier refuses the transfer the caller keeps the AI.

## Open items

- Vobiz answer URLs have no documented signature; authenticity rests on `is_live` (see above).
- The default greetings and the recording notice in Telugu and Hindi need a native speaker's check before launch.
- An employee on a Bulk number rung back by a contact who is not in a campaign's list gets no call-back dialed from a requested time; the message task covers it.
- The auto call-back covers closed and busy lines only. A paused employee or an account out of credits does not trigger one.
- Nothing ticks a call-back task done by itself when the call-back is made; the owner does.
- A transferred call's bridged time is not billed to the owner, but the carrier bills the second leg to the account's carrier balance separately; nothing here reconciles it.
- Overnight opening hours need two windows (a day, then the next).
- Vobiz documents no way to detach a number from an application, so pausing an inbound employee misses the call with a reason instead.
- A trial Vobiz account blocks inbound calls; this needs the carrier account to be fully verified (Track 3, WIRING).

## How to run

```bash
docker compose -f deploy/docker-compose.yml up -d postgres redis
uv run alembic -c services/api/alembic.ini upgrade head && uv run python -m app.voices
AXON_TEST_DATABASE_URL=postgresql+asyncpg://axon:axon@localhost:5432/postgres AXON_TEST_REDIS_URL=redis://localhost:6379/5 uv run pytest
```

Inbound needs the Vobiz keys, `AXON_ENGINE_PUBLIC_URL` and `AXON_API_PUBLIC_URL` (the engine on a public https URL, for instance a cloudflared tunnel). Going live as an inbound employee, or `POST /employees/{id}/inbound/connect`, points the number at `/vobiz/inbound`. The worker runs `summary_tick` every ten minutes (from 8 AM IST it sends the day's summary).
